# 第 1 周：开发板真实传感数据的采集、上送与验证

> 本周问题：学生借助智能体，怎样把开发板的一项真实传感数据采集出来，送到自己的 VPS / Web 平台并验证？

---

## 一、本周问题的答案

本周要把「一块板子上的一个真实物理量」变成「自己平台上一条可核对、可复现的记录」。按四个问题逐条回答：

| 问题 | 答案 |
|------|------|
| 采什么 | QMA7981 三轴加速度计（X / Y / Z 三轴）与芯片内部温度传感器 |
| 怎么采 | 走 I2C 总线：SDA = GPIO4 / SCL = GPIO5，从地址 `0x12`，固件每 100 ms 组一帧上报 |
| 送到哪 | 送到本机服务器 `http://127.0.0.1:8080`，串口（COM4 / 115200）与 WiFi 双通道，**串口优先** |
| 怎么验证 | 一帧对应 `data/records.ndjson` 里一条记录；页面实时值随之变化；同一物理量三单位并存可互算；设备白名单 `expectedDeviceId` 校验通过 |

四条相互独立、缺一不可：**能采到、能送到、能落库、能对上号**。任一条不成立，都不算「完成了一次真实采集」。

---

## 二、板 / 服务端 / 浏览器三方分工

| 角色 | 负责 | 不负责 | 失败时谁先暴露 |
|------|------|--------|----------------|
| 板端（ESP32-S3-EYE 固件） | 读 QMA7981 与芯片温度、组帧、每 100 ms 上报、串口 / WiFi 发送 | 不做业务判断、不落库、不算统计 | 采集或发送失败时板端先停止产生新帧，服务端随即收不到新数据（`live` 转 false） |
| 服务端（`server.js`） | 接收 `POST /api/data`、解析校验、落盘 NDJSON、广播 WebSocket、维护 `state` | 不展示界面、不替板端补数据 | 解析或设备校验失败时，服务端拒绝落库并在 `state` 显示原因 |
| 浏览器（SPA） | 订阅 WebSocket 渲染实时值、查询历史记录 | 不直接读串口、不写数据库、不缓存「上次值」冒充新值 | 数据断流时页面先提示「未更新」（`goStale`），而不是继续显示旧值 |

## 三、器件型号与接线依据

| 项目 | 值 | 依据 |
|------|----|------|
| 加速度计型号 | QMA7981 三轴加速度计 | 板载器件，走 I2C |
| I2C SDA | GPIO4 | ESP-IDF / esp-bsp 官方板级定义 |
| I2C SCL | GPIO5 | ESP-IDF / esp-bsp 官方板级定义 |
| I2C 从地址 | `0x12` | QMA7981 数据手册默认地址 |
| 串口波特率 | 115200 | 固件与 `server.js` 串口参数一致 |
| 串口设备 | COM4 | 本机枚举确认 |
| USB 标识 | VID / PID `303A:1001`（原生 USB-Serial/JTAG） | ESP32-S3 原生 USB 描述符 |

以上引脚与地址全部来自 ESP-IDF 与 esp-bsp 的官方定义以及器件数据手册，**不凭经验猜测**。原生 USB-Serial/JTAG 意味着板子的日志、数据与命令共用同一条 USB 通道，无需额外 USB-TTL 转接。

## 四、单位与时间核对

### 4.1 同一物理量的三种表达

同一物理量同时上报三种单位，是为了让「量程、物理意义、SI 一致性」三件事各有人看：

| 字段 | 含义 | 用途 |
|------|------|------|
| `acc_x_raw` | 原始 ADC 计数 | 看量程与刻度是否合理 |
| `acc_x_g` | 以重力加速度 g 为单位 | 看物理量本身（姿态、重力分量） |
| `acc_x_ms2` | 以 m·s⁻² 为单位 | 与 SI 单位制对齐，便于科学计算 |

实测一帧对照（2026-11-27）：

| 字段 | 实测值 |
|------|--------|
| `acc_x_raw` | -1700 |
| `acc_x_g` | -0.3175 |
| `acc_x_ms2` | -3.114 |
| `temp_c` | 46.8 |
| `rssi` | -26 |

换算关系实测成立：`acc_x_ms2 = acc_x_g × 9.80665`，即 -0.3175 × 9.80665 ≈ -3.114 ✓。
`acc_x_raw` 与 `acc_x_g` 同时上报，便于现场核对量程与刻度；两者的换算比例随量程档位而定，本文不把某个固定比例当作结论。

### 4.2 时间三列

| 列 | 含义 | 当前状态 |
|----|------|----------|
| 板端 `ts` / `board_iso` | 板子自己对时后的采样时刻 | **当前全部为 null（待修复）** |
| 服务端 `recv_ts` / `recv_iso` | 服务端收到该帧的时刻 | 正常，可用于核对 |
| `skew_ms` | 板端时刻与服务端时刻之差 | **当前全部为 null（随板端时间戳一起缺失）** |

**已知缺陷（如实登记）**：`data/records.ndjson` 中全部记录的 `board_ts` / `board_iso` / `skew_ms` 均为 null。根因是固件 `time_sync()` 只在 `app_main` 的 `wifi_wait(15000)` 成功之后调用一次；本次开机时热点不在，SNTP 从未对时，`build_frame` 里 `if (t > 1700000000)` 的闸门一直不成立，帧里就没有 `ts` / `iso` 字段。
修复进行中：在 `IP_EVENT_STA_GOT_IP` 分支补做一次对时（拉起一次性任务 `ntp_resync_task`，不在事件循环里同步阻塞），由 `test/firmware-ntp-resync-test.js` 的 11 项静态契约锁住，**尚未烧录验证**。因此本周「核对单位与时间」只能先核对服务端接收时刻（`recv_ts` / `recv_iso`），板端时刻待烧录后恢复。

## 五、最小接收与存储服务

`server.js` 是单文件 Node 服务，无数据库。`POST /api/data` 的处理链固定为五步：

1. **串口优先**：串口在线时以串口上报为准，忽略同一时刻的 WiFi 上报，避免同帧重复入账；
2. **解析**：把上报行解析为统一字段（`acc_x_raw` / `acc_x_g` / `acc_x_ms2` / `temp_c` / `rssi` / `heap` / `upload_ok` / `upload_fail` / `upload_skip` / `upload_drop` 等）；
3. **落盘**：追加一行到 `data/records.ndjson`，滚动上限 32 MB；
4. **广播**：通过 WebSocket 把新帧推给所有已连接页面；
5. **更新 state**：刷新 `/api/state` 的 `connected` / `live` / `transport` 等状态。

查询接口：

| 接口 | 作用 |
|------|------|
| `GET /api/records` | 分页查询历史记录，返回 `{seq, recv_ts, recv_iso, device_id, device_mac, transport, src_ip, board_ts, board_iso, skew_ms, fields}` |
| `GET /api/records.csv` | 导出 CSV |
| `GET /api/devices` | 列出出现过的设备 |
| `GET /api/state` | 当前连接与设备校验状态 |

存储采用 NDJSON（每行一条 JSON），滚动上限 32 MB，超出后滚动淘汰最旧数据，避免单文件无限增长。

## 八、备用路径与迁移

### 8.1 备用路径：本机作服务器

课程要求「部署到分配的 VPS 空间」，但本项目**没有分到 VPS**，按课程「备用路径」以本机作服务器：`http://127.0.0.1:8080`。`docs/vps-deploy.md` 已写好 Windows Server 一键方案，打开即见「当前状态：未部署」，拿到 VPS 后照做即可，**此处不写成已部署**。

需要讲清楚的一点：**USB 串口在线只能作为排错通道，不能据此认定「独立联网上传」已通过**。本项目当前正是 USB 串口在线（`transport=serial`、`device.path=COM4`）；WiFi 虽已连上，但上传队列在丢帧（`upload_drop` / `upload_fail` 非零），所以「板端脱离 USB、仅靠 WiFi 独立把数据传到平台」这条**尚未取得干净证据**。VPS 故障或网络异常时，可用本机服务定位问题，但不能把「串口通」当成「联网通」。

### 8.2 迁移：为个人项目选定一项设备数据

把本周做法抽象出来，就是「选一项设备数据 → 采集 → 上送 → 落库 → 页面可核对」。迁移到个人项目只需三步：

1. **选定一项设备数据**：明确采什么物理量、单位是什么、采样频率多少；
2. **打通一条上送链路**：设备 → 服务端 → 落库，并保留原始值用于核对；
3. **做一次可复现的验证**：一帧对应一条记录，页面实时值与记录一致，断流时提示「未更新」而不是显示旧值。
